# `/loop` Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give OpenMod a `/loop` slash command with an interval mode and an until-done mode, where the agent can end the task itself in interval mode and must report completion or blockage in until-done mode.

**Architecture:** A new core service, `Loop.Service`, holds one record per session in the existing `kv` table (no new table, so nothing in machine-generated `schema.gen.ts` churns and upstream merges stay cheap). It prompts through the existing `Session.Service.prompt`, waits for `session.status` idle events on the existing `Bus`, and exposes two model-facing tools, `loop_complete` and `loop_blocked`, registered as an internal plugin the same way `AutomationTools` is. The `/loop` command is registered through the plugin command editor, exactly as `automation` registers its command today.

**Tech Stack:** TypeScript, Bun 1.4.4, Effect (Context.Service, Layer, Stream, FiberMap, TestClock), SolidJS TUI over OpenTUI, `bun test`.

**Spec:** `docs/superpowers/specs/2026-11-19-loop-telegram-design.md`

## Global Constraints

- Test runner: `bun test`. Core tests use `testEffect(...)` from `packages/core/test/lib/effect.ts`, which supplies `TestClock` and refuses non-loopback network.
- Core service files start with `export * as <Name> from "./<file>.js"` and define `export class Service extends Context.Service<Service, Interface>()("@opencode/<Name>") {}`.
- Import specifiers inside `packages/core/src` end in `.js`; test files import from `@opencode/core/...` with no extension.
- No new database table. Loop state lives in `kv` under the key prefix `loop:`.
- Every cap is a named exported constant: `MAX_ITERATIONS = 25`, `MAX_WALL_CLOCK_MS = 4 * 60 * 60 * 1000`, `NO_PROGRESS_LIMIT = 2`.
- Default delivery for loop-dispatched prompts is `"queue"`, never `"steer"`, so a loop run never interrupts an in-flight turn.
- Nothing bypasses permissions. A run is an ordinary session run.

## Review Focus

- **A session that is already busy when the loop starts.** Expected: the loop does not stack a second run; it waits for idle. Pinned in Task 4.
- **`/loop` typed twice in one session.** Expected: the second replaces the first rather than leaving two loops prompting the same session, and the user is told which one was abandoned. Pinned in Task 6.
- **The service restarts mid-loop.** Expected: the loop resumes from its stored iteration rather than restarting at 1 or dying. Pinned in Task 3.
- **An instruction that makes no tool call and changes no file, twice in a row.** Expected: the loop pauses as `no-progress` instead of spending the remaining iterations. Pinned in Task 7.
- **`loop_blocked` called after a `loop_stop`.** Expected: the stop wins; a late completion must not resurrect a stopped loop. Pinned in Task 5.

```typescript
// packages/core/test/loop-state.test.ts
import { describe, expect, test } from "bun:test"
import { MAX_ITERATIONS, NO_PROGRESS_LIMIT, afterIdle, end, start } from "@opencode/core/loop/state"
import type { Request } from "@opencode/core/loop/parse"

const started = (request: Extract<Request, { kind: "start" }>) => start({ sessionID: "ses_one", request, now: 1_000 })
const interval = started({ kind: "start", mode: "interval", intervalMs: 300_000, instruction: "check" })
const untilDone = started({ kind: "start", mode: "until-done", instruction: "fix" })

describe("start", () => {
  test("begins the first iteration as running", () => {
    expect(interval.iteration).toBe(0)
    expect(interval.state).toBe("running")
    expect(interval.noProgress).toBe(0)
  })
})

describe("afterIdle", () => {
  test("until-done prompts again immediately", () => {
    const result = afterIdle({ ...untilDone, iteration: 1 }, { now: 2_000, progressed: true })
    expect(result.action).toBe("prompt")
    expect(result.record.iteration).toBe(2)
  })
  test("interval waits out the rest of the interval before prompting", () => {
    const result = afterIdle({ ...interval, iteration: 1, lastRunAt: 1_000 }, { now: 1_000 + 120_000, progressed: true })
    expect(result.action).toBe("wait")
    expect(result.waitMs).toBe(180_000)
    expect(result.record.state).toBe("waiting")
  })
  test("interval that has already overrun its interval prompts at once", () => {
    const result = afterIdle({ ...interval, iteration: 1, lastRunAt: 1_000 }, { now: 1_000 + 400_000, progressed: true })
    expect(result.action).toBe("prompt")
    expect(result.record.iteration).toBe(2)
  })
  test("two iterations without progress end the loop instead of continuing", () => {
    const twice = { ...untilDone, iteration: 2, noProgress: NO_PROGRESS_LIMIT - 1 }
    const result = afterIdle(twice, { now: 2_000, progressed: false })
    expect(result.action).toBe("end")
    expect(result.record.endReason).toBe("no-progress")
  })
  test("progress resets the no-progress counter", () => {
    const result = afterIdle({ ...untilDone, iteration: 2, noProgress: 1 }, { now: 2_000, progressed: true })
    expect(result.record.noProgress).toBe(0)
  })
  test("the iteration cap ends the loop and is not exceeded", () => {
    const result = afterIdle({ ...untilDone, iteration: MAX_ITERATIONS }, { now: 2_000, progressed: true })
    expect(result.action).toBe("end")
    expect(result.record.endReason).toBe("max-iterations")
    expect(result.record.iteration).toBe(MAX_ITERATIONS)
  })
  test("the wall-clock cap ends the loop", () => {
    const result = afterIdle({ ...untilDone, iteration: 1 }, { now: 1_000 + 4 * 60 * 60 * 1000, progressed: true })
    expect(result.action).toBe("end")
    expect(result.record.endReason).toBe("max-wall-clock")
  })
})

describe("end", () => {
  test("a blocked loop pauses so a reply can resume it", () => {
    const paused = end({ ...untilDone, iteration: 3 }, "blocked", "need credentials")
    expect(paused.state).toBe("paused")
    expect(paused.endReason).toBe("blocked")
    expect(paused.note).toBe("need credentials")
    expect(paused.iteration).toBe(3)
  })
  test("a completed loop is ended, not paused", () => {
    expect(end(untilDone, "completed").state).toBe("ended")
  })
})
```

```typescript
// packages/core/test/lib/kv.ts
import { Effect, Layer, Ref } from "effect"
import { KV } from "@opencode/core/kv"

/** An in-memory KV, so services that persist through kv run without a database. */
export const memoryKV: Layer.Layer<KV.Service> = Layer.effect(
  KV.Service,
  Effect.gen(function* () {
    const cells = yield* Ref.make(new Map<string, unknown>())
    return KV.Service.of({
      get: (key) => Ref.get(cells).pipe(Effect.map((map) => map.get(key))),
      set: (key, value) => Ref.update(cells, (map) => new Map(map).set(key, value)),
      remove: (key) =>
        Ref.update(cells, (map) => {
          const next = new Map(map)
          next.delete(key)
          return next
        }),
      scan: (options) =>
        Ref.get(cells).pipe(
          Effect.map((map) => ({
            entries: [...map.entries()]
              .filter(([key]) => key.startsWith(options.prefix))
              .map(([key, value]) => ({ key, value })),
          })),
        ),
    })
  }),
)
```

### Task 4: Run the loop — prompt, wait for idle, repeat

**Files:**
- Create: `packages/core/src/loop/runner.ts`
- Test: `packages/core/test/loop-runner.test.ts`

**Interfaces:**
- Consumes: `Loop.Service` (Task 3), `State.afterIdle` (Task 2), a session `prompt`, `Bus.Interface`.
- Produces:
  - `export type SessionPort = { readonly prompt: (input: { sessionID: SessionSchema.ID; text: string; delivery: "steer" | "queue" }) => Effect.Effect<void, unknown> }`
  - `export function awaitIdle(bus: Bus.Interface, sessionID: string): Effect.Effect<void, never, Scope.Scope>` — completes when a `session.status` event for `sessionID` arrives with `status.type === "idle"`; already-idle never fires the event, so the caller checks the session's active set first.
  - `export function drive(input: { loop: Loop.Interface; sessions: SessionPort; bus: Bus.Interface }): Effect.Effect<void, never, Scope.Scope>` — the per-session driver: while the record is `running` or `waiting`, wait for idle (or the interval), dispatch the next prompt with `delivery: "queue"`, and apply `afterIdle`. Registered per session in a `FiberMap` so two sessions never share a driver. `SessionPort` is small on purpose: it is what a test can stub, and the real `Session.Service` satisfies it structurally.

`awaitIdle` filters the bus stream on `sessionID` and `status.type === "idle"`; it must not resolve on `busy` or `retry`. `drive` keeps one fiber per session in a `FiberMap`, mirrors `Automation`'s per-run election so two drivers cannot race one session, and uses `Effect.sleep` for the interval remainder so `TestClock` can advance it without real waiting. When the record is already `ended` or `paused`, `drive` starts nothing and returns.

`drive` is also what makes the state machine take effect — nothing else writes these fields:

- **Before each dispatch:** `loop.put({ ...record, lastRunAt: now })`, so the next interval is measured from when this run actually started. Without the stamp, an interval loop's remainder is measured from an absent `lastRunAt` and always reads as zero elapsed.
- **After each dispatch and idle:** `loop.put(afterIdle(record, { now, progressed }).record)`. `afterIdle` is pure and returns the transitioned record; the caller is what persists it, and a `wait` action sleeps `waitMs` before prompting again.
- **On `action === "end"`:** the `put` above already stored the end state; the driver then stops looping for that session.
